## Context

29 tests fail because the 4-state log status model (`status: 'completed'|'failed'|'skipped'`) was implemented in the handlers but two handlers pass synthetic rows with the old `completed: boolean` field, the store's `getCachedWeekCompletions` checks the old field, and twelve test files still assert/construct logs using the old model. Full root cause analysis in CONTEXT.md.

### Task 8 — Fix mastery-cadence.test.js makeLogs function

**File**: `tests/integration/mastery-cadence.test.js`

Find the `makeLogs` helper function:
```js
function makeLogs(habitId, dates, completed = true) {
  return dates.map(date => ({ habitId, date, completed }));
}
```
Replace with:
```js
function makeLogs(habitId, dates, isCompleted = true) {
  return dates.map(date => ({ habitId, date, status: isCompleted ? 'completed' : 'failed' }));
}
```

**Why**: `mastery.js` evaluates `log.status === 'completed'` for binary habits. Fixtures with `{completed: true}` have no `status` field → completedCount is always 0 → mastery is never reached.

### Task 13 — Fix import.integration.test.js broadcastSpy shape

**File**: `tests/integration/import.integration.test.js`

Find the `makeBroadcastSpy` function (around line 61):
```js
function makeBroadcastSpy() {
  const messages = [];
  return {
    messages,
    postMessage(msg) { messages.push(msg); },
  };
}
```
Replace with:
```js
function makeBroadcastSpy() {
  const messages = [];
  const spy = (msg) => messages.push(msg);
  spy.messages = messages;
  return spy;
}
```

**Why**: `import.js` calls `_broadcast({ type: 'import:done' })` — it expects a callable function. The old spy was a `{ postMessage }` object, not a function. `TypeError: _broadcast is not a function`.

**Verify**: `node --test tests/integration/import.integration.test.js` exits 0.
