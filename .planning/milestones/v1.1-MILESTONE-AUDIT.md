### Boot Sequence Order (cross-shell)

Both `main.js` (mobile) and `desktop.js` (desktop) share the same boot contract:

```
configureScheduled({repo})   ← Phase 07 DI
...
await bootSeed()
await bootScheduled()        ← before hydrate — ensures correct statuses in IDB
await hydrate()              ← cache pre-warmed with promoted statuses
mountRoutes(...)             ← views render with correct data
```

**Verified:** `bootScheduled` runs before `hydrate` in both shells. Phase 08/09 views always see up-to-date statuses.

### Store Subscription Re-render Chain

```
apply({type: 'promoteHabit'})
  → IDB atomic write (habits + events + meta.undoToken)
  → broadcast({type: 'mutation', ...})
  → notify({event: 'promoteHabit', keys: {habitId}})
  → store._subscribers.forEach(fn())
    → catalog.js re-filters habits (Phase 08)
    → wavePlanning.js rerenderSection() (Phase 09)
```

**Verified:** Both view consumers re-render on the same apply/notify/subscribe chain.
