mobile-first daily check-in with desktop analytics and the full S1/S2/S3 scoring trio.

## Milestone Summary

**Key Decisions (locked during milestone):**

- Vanilla multi-file static app, IndexedDB, no build — mirrors `mindful-breathing` constraint
- 7 IDB stores declared at v1 including score_snapshots (forward-compatible with Phase 6)
- BroadcastChannel('habits') for cross-tab sync; channel name namespace-aligned with cache + DB
- Module SW (type:'module') — replaces planned classic SW after importScripts SyntaxError (D-29)
- JSDoc as comment standard; inline `//` only for "why" notes (D-27)
- SemVer 0.y.z during development; 0.1.0 → 0.5.0 across 6 phases (D-28)
- Single-mutator chokepoint via apply.js HANDLERS (DATA-04); views never write to IDB directly
- Habit-definition edits create habit_versions rows; historical logs reference effective version
- score_snapshots written at log-write time; views read snapshots, never call scoring.js (SCORING-08)
- Two HTML shells (index.html mobile, desktop.html analytics); not one responsive layout (D-04)
- CSV export: semicolon delimiter, UTF-8 BOM, CRLF for Polish Windows Excel compatibility

**Issues Resolved During Milestone:**

- Module SW SyntaxError (importScripts + export const): switched to `{type:'module'}` (D-29)
- Phase 5 DI seam not wired at boot (BLOCKER-01): configureExport/Import/BackupNag calls added to main.js
- Cross-tab sync onMessage never registered (BLOCKER-02/03): registered in main.js + desktop.js boot
- analytics.js wave names via store.cache.waves (unreachable): replaced with getWave() from wave.js
- Phase 2 `BroadcastChannel('nawyki')` renamed to `'habits'` in requirements vs implementation (doc drift)
- Phase 3 `[ ]` checkbox on ROADMAP.md and REQUIREMENTS.md (verification doc inconsistency)

**Issues Deferred (Backlog):**

- Completion visualization for numeric/slot habits (low effort, v1.1 candidate)
- Polish name ⓘ button missing on numeric/slot habit rows
- Wave management UI (waves are static seed data; no create/edit/delete)
- Import JSON UI label not visible (raw `<input type="file">` only)
- First-class waves data model (currently wave is a plain string field; no `waves` IDB store)

**Technical Debt Incurred:**

- Phase 2 has no VERIFICATION.md (accepted: UAT 10/10 + REQUIREMENTS.md checkboxes substitute)
- REQUIREMENTS.md Phase 1 checkboxes show `[ ]` (cosmetic; VERIFICATION.md is authoritative)
- 2 intentional stub failures in test suite (mastery-cadence.test.js, wave-aggregates.test.js — pre-existing Phase 4 stubs, documented)
