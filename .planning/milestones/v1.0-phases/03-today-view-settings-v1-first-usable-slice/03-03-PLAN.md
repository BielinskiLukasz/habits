  <behavior>
    Goal: after `apply()` resolves, calling `render()` in any subscriber must read CURRENT cache state (not the pre-tap snapshot). Pre-03-03, `hydrate()` populates cache once at boot and is `idempotent`; new mutations were not reflected in `cache.logs` or `cache.habits` until manual re-hydrate. This is Pitfall 2 — the optimistic flip would briefly disagree with the cache, and a `store.subscribe(render)` would re-render the pre-tap state.

    New behavior: each `notify({event, keys})` call (which `apply.js` fires once per successful tx) triggers an in-process `refreshHydratedKeys(keys)` that re-reads the affected log row + habit row from the repo and updates the cache BEFORE invoking subscriber callbacks.

    `refreshHydratedKeys(keys)`:
    - If `keys.habitId` present:
      - `const habit = await _repo.getHabit(keys.habitId)`; if defined, `cache.habits.set(keys.habitId, habit)`; if undefined, `cache.habits.delete(keys.habitId)` (defensive — habit row was removed).
    - If `keys.habitId` AND `keys.date` both present:
      - `const log = await _repo.getLog(keys.habitId, keys.date)`; if defined, `cache.logs.set(\`${keys.habitId}::${keys.date}\`, log)`; if undefined, `cache.logs.delete(\`${keys.habitId}::${keys.date}\`)` (defensive — handles `restoreLogRow` deletes).
    - If `keys.key` present (settings rows, see Slice 4): `const setting = await _repo.getSetting(keys.key); if (setting) cache.settings.set(keys.key, setting.value); else cache.settings.delete(keys.key);` — Slice 4 wires this; in Slice 3 the conditional is harmless.

    `notify(payload)` (extension):
    - Existing behavior: fan out to every `subs` callback.
    - New: if `payload?.keys`, `await refreshHydratedKeys(payload.keys)` BEFORE fanning out. Subscribers see fresh cache.
    - Sync callers (`notify()` with no payload, or no `keys`) skip the refresh — no regression.

    Cross-tab path (BroadcastChannel via `js/platform/sync.js`): the existing P2 BroadcastChannel listener already calls `notify({event, keys})` on receiving an envelope. With this change, peer-tab broadcasts ALSO trigger a re-hydrate of the affected rows.
