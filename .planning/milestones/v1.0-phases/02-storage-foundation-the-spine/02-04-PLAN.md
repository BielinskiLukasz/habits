## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| seed/habits.json → IDB | Bundled JSON crosses from disk → fetch → IDB write. Schema-validate before merge to defend against prototype pollution. |
| `navigator.storage.persist()` | Browser-prompt surface; first-launch UX cost. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Tampering | Seed-merge clobbering user-edited rows | mitigate | Seed loader merges by `id` only; iterates `seed.habits` and skips any whose `id` is in `meta.seededIds` (D-33 + Pitfall 5). Integration test asserts a second boot does NOT overwrite a hand-edited `habits[id]` row. Severity: HIGH — this is the data-trust invariant. |
| T-02-05 | Denial of Service (storage eviction) | `navigator.storage.persist()` denial | mitigate | `persist()` result recorded in `meta.persistResult`; diagnostics panel surfaces the value (P3); Pitfall 3 — `false` on Chrome first-launch is non-fatal, NOT user denial. |
| T-02-XSS | Tampering | Seed JSON injection via maliciously-crafted habit name | mitigate | `seed/habits.json` is committed source under the developer's control (no remote fetch); JSON.parse is safe against prototype pollution by default; the loader schema-validates each habit's required fields (`id`, `name`, `wave`, `cadence`) and rejects malformed entries. |
| T-02-PERSIST11 | Tampering | Persist re-probed on every boot (Pitfall 11) | mitigate | After `persist()` resolves, write `meta.persistResult`. Subsequent boots check the flag and skip the re-probe. Integration test asserts second boot does NOT call persist again. |
| T-02-SCHEMA | Tampering | Seed cadence shape drift between P2 and P4 (Pitfall 12) | mitigate | Each cadence record carries `cadence_v: 1`. P4's cadence engine dispatches on the version; the seed is forward-compatible. |
</threat_model>
