## Context

### score_snapshots Row Shape (single row per habitId+date, all 3 models)

The locked `score_snapshots` schema has `keyPath: ['habitId', 'date']` (ONE row per pair). All three model scores are embedded in a single row:

```javascript
{
  habitId: string,      // IDB key field 1
  date: string,         // IDB key field 2 (YYYY-MM-DD)
  s1Score: number|null, // 0–100 rolling %, or null during grace period
  s1Status: 'Healthy'|'Watch'|'At-risk'|'Failing'|null,
  s2Score: number|null, // 0–1 weighted score, or null during grace period
  s3Score: number|null, // 0–1 load-adjusted score, or null during grace period
  scoreVersion: 1,      // locked at 1 for Phase 6
}
```

### Write-time trigger context (D-114)

`writeHabitSnapshots(habitId, repo)`:
- Fetches all logs for `habitId` from IDB via `repo.getLogsByHabit(habitId)`
- Fetches the habit definition from `repo.getHabit(habitId)` (or `repo.getAllHabits()` filtered)
- Fetches all active habits for S3 load denominator via `repo.getAllHabits()` (or pass allHabits in)
- Fetches settings (`globalThreshold`, `globalWindow`, `weekStart`) from `repo.getSetting()`
- Determines the date range to recompute: from `habit.createdAt` up to today (or the last log date, whichever is later)
- For each date in the range, calls `computeS1`, `computeS2`, `computeS3` from `js/domain/scoring.js`
- Writes each result as a `score_snapshots` row via `repo.runTx` — uses a single IDB transaction per habit to minimize overhead
- This function is called from `apply.js` after any log-mutating event (wire-up happens in Plan 06-03)

`rebuildAllSnapshots(repo, onProgress)`:
- Fetches all habits (including archived) via `repo.getAllHabits()`
- Fetches settings once
- For each habit, calls `writeHabitSnapshots(habit.id, repo)` sequentially
- `onProgress(done, total)` callback invoked after each habit completes (for Settings loading state)
- NFR-03: must complete < 2 s for 5 years × 65 habits. Strategy:
  - Batch all logs for a habit with a single IDB range query (by habitId index)
  - Compute all days for the habit in a synchronous loop (no per-day IDB reads)
  - Write all snapshot rows for a habit in a single `runTx` call (one transaction, all rows)
  - Fetch `allHabits` once outside the habit loop (needed for S3 load denominator on every day)

### repo API surface used (existing in repo.js)
- `repo.getAllHabits()` → Promise\<habit[]\>
- `repo.getLogsByHabit(habitId)` → Promise\<log[]\> (all logs for one habit, any date)
- `repo.getSetting(key)` → Promise\<any\>
- `repo.runTx(storeNames, mode, fn)` → Promise\<void\>

The write inside `runTx`: `tx.objectStore('score_snapshots').put(snapshotRow)` for each date row.

### Test approach

Use `tests/helpers/fake-idb.js` pattern. The test injects:

- Mocked `computeS1/S2/S3` functions (avoid depending on 06-01 being merged first — mock them to return fixed values)
- Verify that the correct snapshot shape lands in the fake store

At module load, auto-configure with real scoring functions:

```javascript
import { computeS1, computeS2, computeS3 } from '../domain/scoring.js';

```

**`writeHabitSnapshots(habitId, repo)` implementation:**
1. Fetch habit: `const habit = (await repo.getAllHabits()).find(h => h.id === habitId)` — return early if not found
2. Fetch all habits (for S3 load): `const allHabits = await repo.getAllHabits()`
3. Fetch logs: `const logsForHabit = await repo.getLogsByHabit(habitId)`
4. Fetch settings: `const globalThreshold = (await repo.getSetting('masteryThreshold')) ?? 90` and `const windowDays = (await repo.getSetting('masteryWindow')) ?? 70` and `const weekStart = (await repo.getSetting('weekStart')) ?? 'mon'`
5. Build `ctx` matching the shape `mastery.js` expects: `{ appliesToday, windowDays, globalThreshold, weekStart, weekCompletions: () => 1, monthCompletions: () => 1, evaluationDate: todayYMD }`
   - `appliesToday`: import from `../domain/cadence.js` — `import { appliesToday } from '../domain/cadence.js'`
6. Determine date range: `startDate = habit.createdAt` (YYYY-MM-DD), `endDate = todayYMD` from `js/util/date.js` `toYMD(new Date())`
7. Iterate each date from startDate to endDate using `daysFrom`:
   - For each `dateYMD`, set `ctx.evaluationDate = dateYMD`
   - Call `_computeS1(habit, logsForHabit, ctx)`, `_computeS2(habit, logsForHabit, ctx)`, `_computeS3(habit, logsForHabit, ctx, allHabits)`
   - Collect snapshot row: `{habitId, date: dateYMD, s1Score, s1Status, s2Score, s3Score, scoreVersion: 1}`
8. Write all rows in ONE `runTx` call:
   ```javascript
   await repo.runTx(['score_snapshots'], 'readwrite', (tx) => {
     for (const row of snapshotRows) {
       tx.objectStore('score_snapshots').put(row);
     }
   });
   ```

**`rebuildAllSnapshots(repo, onProgress = () => {})` implementation:**
1. `const habits = await repo.getAllHabits()`
2. For each habit in sequence: `await writeHabitSnapshots(habit.id, repo)` then `onProgress(i + 1, habits.length)`

**Performance note for NFR-03:**
- The sequential per-habit loop is deliberately NOT parallelized (avoid IDB tx contention)
- The single `runTx` per habit with all rows is the key to < 2 s: for 5 years × 1 habit = ~1825 rows, a single tx is orders of magnitude faster than 1825 individual puts
- For 65 habits × 1825 dates ≈ 118,625 total put operations — all in 65 transactions, each with ~1825 rows — well within the 2 s budget on modern browsers

**Date iteration helper** (inline in scoreSnapshots.js, no new export):
```javascript
// Iterate from startYMD to endYMD inclusive, yielding each YYYY-MM-DD string.
function* dateRange(startYMD, endYMD) {
  let cur = startYMD;
  while (cur <= endYMD) {
    yield cur;
    cur = daysFrom(cur, 1);
  }
}
```

Import `daysFrom` from `../util/date.js`.
