  <name>Monthly cadence resolver + future-startDate guard + date helpers</name>

  <behavior>
**date.js new helpers:**

- `isInGracePeriod(createdAt: string, today: string, graceDays?: number): boolean`
  - `isInGracePeriod('2026-06-04', '2026-06-10', 7)` → true (day 6, within 7-day grace)
  - `isInGracePeriod('2026-06-04', '2026-06-11', 7)` → false (day 7 = grace ends on day 7 → grace is STRICTLY less than graceDays; day 7 is the 8th calendar day counting from createdAt = day 0 → `daysBetween(createdAt, today) < graceDays`)
  - `isInGracePeriod('2026-06-04', '2026-06-04', 7)` → true (same day = day 0)
  - Default `graceDays` = 7

- `getMonthStart(ymd: string): string`
  - `getMonthStart('2026-03-15')` → `'2026-03-01'`
  - `getMonthStart('2026-03-01')` → `'2026-03-01'`
  - `getMonthStart('2026-01-31')` → `'2026-01-01'`
  - `getMonthStart('2028-02-29')` → `'2028-02-01'`

- `getMonthEnd(ymd: string): string`
  - `getMonthEnd('2026-02-15')` → `'2026-02-28'`
  - `getMonthEnd('2028-02-15')` → `'2028-02-29'` (leap year)
  - `getMonthEnd('2026-01-15')` → `'2026-01-31'`
  - `getMonthEnd('2026-12-01')` → `'2026-12-31'`

**cadence.js extensions:**

- `RESOLVERS['monthly']` — once per calendar month. Evaluates as: `ctx.monthCompletions(habitId, monthStart, monthEnd) === 0` (same pattern as weekly). If no month completions in the current calendar month, habit applies today.
  - Monthly resolver adds `ctx.monthCompletions: (habitId, startYMD, endYMD) => number` to the ctx contract (mirrors `weekCompletions`).

- `appliesToday(habit, date, ctx)` now guards on `habit.startDate`: if `habit.startDate` is defined AND `habit.startDate > date`, return `false` immediately (habit is future-scheduled). This check runs BEFORE resolver dispatch.
  - `appliesToday({cadence:{type:'daily'}, startDate:'2026-07-01'}, '2026-06-15', ctx)` → false
  - `appliesToday({cadence:{type:'daily'}, startDate:'2026-06-15'}, '2026-06-15', ctx)` → true (startDate = today is fine)
  - `appliesToday({cadence:{type:'daily'}, startDate: undefined}, '2026-06-15', ctx)` → true (no startDate = always applies from createdAt)

**DST test cases (extend cadence.test.js):**
  - every-n-days cadence: daysBetween('2026-03-28', '2026-03-30') = 2 (crosses spring-forward, Math.round must not truncate to 1)
  - every-n-days cadence: daysBetween('2026-10-24', '2026-10-26') = 2 (crosses fall-back)
  - day-of-week-subset: 2028-02-29 is a Wednesday (leap day); a 'wed' habit applies
  </behavior>

  <implementation>
**date.js:**
- `isInGracePeriod(createdAt, today, graceDays = 7)`: return `daysBetween(createdAt, today) < graceDays`. Uses existing `daysBetween`. Zero-arg graceDays defaults to 7.
- `getMonthStart(ymd)`: parse with `parseLocalYMD`, set day to 1 via `new Date(y, m-1, 1)`, return `formatLocalYMD`. Use the local-calendar constructor (no setDate needed).
- `getMonthEnd(ymd)`: parse, use `new Date(y, m, 0)` (day 0 of next month = last day of current month), return `formatLocalYMD`. This is the DST-safe, leap-year-aware idiom.

**cadence.js:**
- Add `monthly` entry to `RESOLVERS`: `(h, d, ctx) => { const start = getMonthStart(d); const end = getMonthEnd(d); return ctx.monthCompletions(h.id, start, end) === 0; }`. Import `getMonthStart`/`getMonthEnd` from `../util/date.js`.
- In `appliesToday`: add early-return guard: `if (habit.startDate && habit.startDate > date) return false;` BEFORE the `const resolver = RESOLVERS[habit.cadence.type]` line.
- File header `@file` comment: add `monthly` and `startDate` guard to the documented behavior list. Update the discipline grep expectations (the existing test checks for `RESOLVERS` identifier and absence of `switch`; the new `monthly` entry is already in the table so the test will still pass).
  </implementation>
