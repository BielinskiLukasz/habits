# Phase 9 — UI Design Contract

> Visual and interaction contract for the Desktop Waveboard Wave Planning section.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> Scope: A new Wave Planning accordion section inserted above the existing 12-week
> S1 heat-map on `desktop.html #waveboard`. Implements WAVE-01, WAVE-02, WAVE-03, WAVE-04.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — vanilla HTML/CSS/JS |
| Icon library | Unicode symbols only (▶ / ▼ for chevron via CSS rotation) |

## Spacing Scale

All values are pre-declared in `css/tokens.css`. No new spacing tokens are introduced.

| Token | CSS Variable | Value | Usage in this phase |
|-------|-------------|-------|---------------------|
| xs | --space-1 | 4px | Badge vertical padding |
| sm | --space-2 | 8px | Chevron-to-name gap, badge horizontal padding |
| md-tight | --space-3 | 12px | Wave header vertical padding, scheduled sub-header padding |
| md | --space-4 | 16px | Wave header horizontal padding, habit row horizontal padding |
| lg | --space-5 | 24px | Wave Planning section top margin, habit list left indent |
| xl | --space-6 | 32px | Separator margin between Wave Planning and heat-map |
| 2xl | --space-7 | 48px | Not used in this phase |

Exception — `--space-3 (12px)`: `--space-3: 12px` is declared in `css/tokens.css` (line 31) as a
pre-existing project token used across every phase. 12px falls outside the standard 8-point scale
{4, 8, 16, 24, 32, 48, 64} but is embedded throughout the codebase; replacing it would require
cross-cutting changes to all phases. This phase inherits `--space-3` as-is for wave header vertical
padding, scheduled sub-header padding, habit row gap, and promote button padding. No new out-of-scale
values are introduced.

## Visual Hierarchy

Primary visual anchor: the Wave Planning section title ("Wave Planning") and the health badge column
draw the eye first; the existing 12-week S1 heat-map is secondary and appears below after scrolling.
Within each expanded wave row, the wave name and health badge are the focal points; cadence/date
metadata is visually subordinate (rendered in `--color-fg-muted`).

## DOM Contract

Structural hierarchy for the new section. Built via `buildWavePlanningSection()` → `mount()` per
the D-26 / Pattern S8 builder convention. No `.innerHTML`. All element types are explicit.

```
section.waveplanning
  h2.waveplanning-title                        "Wave Planning"

  div.waveplanning-wave                        × 10 (Wave 0 – Wave 9, order from getAllWaves())
    button.waveplanning-wave-header            [aria-expanded="false"]
                                               [aria-controls="wave-{N}-list"]
                                               [aria-label="Toggle habit list for Wave {N}"]
      span.waveplanning-chevron                "▶"
      span.waveplanning-wave-name              "Wave {N} — {theme}"
      span.waveplanning-wave-meta
        span.waveplanning-wave-date            "{YYYY-MM-DD}"
        span.waveplanning-wave-counts          "{N} active · {N} scheduled"
        span.waveplanning-badge
             .waveplanning-badge--{slug}       "{label}"  (Healthy/Watch/At Risk/Failing/No data/Upcoming)

    ul.waveplanning-habit-list                 [id="wave-{N}-list"]  [hidden]
      ── active/mastered habits ──
      li.waveplanning-habit-row                × (active + mastered habits)
        span.waveplanning-habit-name           "{habit.name}"
        span.waveplanning-habit-status         "active" | "mastered"
        span.waveplanning-habit-stage          "{stage label}"
        span.waveplanning-habit-cadence        "Daily" | "Mon/Wed/Fri" | "Every 2 days" …

      ── only if scheduled habits exist in this wave ──
      h3.waveplanning-scheduled-heading        "Scheduled"

      li.waveplanning-scheduled-row            × (scheduled habits, sorted by startDate asc)
        span.waveplanning-habit-name           "{habit.name}"
        span.waveplanning-scheduled-date       "{habit.startDate}"
        button.waveplanning-promote-btn        [aria-label="Promote {habit.name} to active"]
                                               "Promote to active"

      ── only if 0 habits total in this wave ──
      li.waveplanning-empty                    "No habits in this wave."

hr.waveplanning-heatmap-separator

(existing 12-week S1 heat-map — unchanged)
```

Notes:
- `button.waveplanning-wave-header` is a real `<button>` element for native keyboard support.
- `ul.waveplanning-habit-list` uses the `[hidden]` attribute (not a CSS class) for collapsed state.
- `waveplanning-scheduled-heading` is `<h3>` — semantic sub-heading inside the expanded list.
- No `switch` in builder code — use dispatch table (Anti-Pattern 4).
- No direct `indexedDB` calls — use `getCachedHabits()` and `repo.getSnapshotsInRange()` (Anti-Pattern 1).

## Interaction Contract

### Wave header: expand / collapse

- Element: `button.waveplanning-wave-header`
- Trigger: click, Enter, Space
- Default state: collapsed — `aria-expanded="false"`, `ul[hidden]`
- On toggle: flip `aria-expanded` ("false" → "true"), remove/add `hidden` attribute on the `ul`
- Visual: `.waveplanning-chevron` rotates 90° via CSS `transition: transform 0.15s ease`
- No animation on list open/close — `[hidden]` attribute is instant (acceptable; no JS animation)
- Expand state is per-wave and independent (expanding Wave 3 does not collapse Wave 5)

### Promote to active

- Element: `button.waveplanning-promote-btn`
- Trigger: click
- Action: call `apply({ type: 'habit:promote', habitId })` → reuses `promoteHabit.js` unchanged
- No confirmation dialog (D-13, consistent with Phase 8 Catalog promote)
- In-flight guard: set `button.disabled = true` on click; re-render removes it automatically
- On success: BroadcastChannel `{type: 'habit:put', habitId}` fires → `store.subscribe` callback triggers section re-render

### Live re-render after promote

- Trigger: `store.subscribe(fn)` callback (existing pattern from waveboard.js)
- Re-render scope: full `.waveplanning` section — call `buildWavePlanningSection()` → `mount()` into `.waveplanning` container
- Expanded-state preservation: before re-render, read `aria-expanded` from each `.waveplanning-wave-header` and store in a Map keyed by wave number; after mount, restore each header's `aria-expanded` and the corresponding `ul[hidden]` attribute
- Focus: not explicitly managed — re-render is transparent to the user
