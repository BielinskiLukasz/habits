## Component Specifications

### Upcoming Section Container

**Element:** `<section class="catalog-upcoming-section">`

**Structure:**
```
<section class="catalog-upcoming-section">
  <h2 class="catalog-upcoming-heading">Upcoming</h2>
  <ul class="catalog-upcoming-list">
    <!-- Upcoming list items go here -->
  </ul>
</section>
```

**Styling:**
- Display as a vertical flex column (stacked list)
- Margin-top: `var(--space-5)` (24px) — visual separation from active list above
- Padding: `var(--space-2)` (8px) horizontal, no vertical padding (items handle vertical spacing)
- Background: transparent (inherits page background)
- Border-top: optional subtle 1px separator line using `var(--color-border)` (rgba(255, 255, 255, 0.08))

**Visibility (D-10):**
- Hidden entirely when the `habits` array has no `status === 'scheduled'` items
- **Implementation:** Conditional rendering in catalog.js — `if (upcomingHabits.length > 0) { renderUpcomingSection(...) }`
- No empty-state message; section does not exist in DOM when empty

### Upcoming Section Heading

**Element:** `<h2 class="catalog-upcoming-heading">Upcoming</h2>`

**Styling:**
- Font size: `var(--text-lg)` (18px)
- Font weight: 600 (semibold)
- Line height: 1.2
- Margin: `0 0 var(--space-2) 0` (bottom margin 8px to next element)
- Padding: 0
- Color: `var(--color-fg)` (#f5f5f5)
- Letter-spacing: normal

**Role:** Section label; matches the style and intent of existing section headers in the codebase (e.g., "Catalog" header).

### Upcoming List Item

**Element:** `<li class="catalog-upcoming-item">`

**Structure (per D-01, D-02, D-03):**
```
<li class="catalog-upcoming-item">
  <div class="catalog-habit-info">
    <span class="catalog-habit-name">Morning walk</span>
    <div class="catalog-habit-badges">
      <span class="catalog-habit-wave">Wave 0</span>
      <span class="catalog-upcoming-date">2026-08-15</span>
    </div>
  </div>
  <div class="catalog-habit-actions">
    <button class="catalog-btn catalog-btn--edit" data-action="edit" data-habit-id="{id}" aria-label="Edit Morning walk">Edit</button>
    <button class="catalog-btn catalog-btn--promote" data-action="promote" data-habit-id="{id}" aria-label="Promote Morning walk to active">Promote</button>
  </div>
</li>
```

**Layout:**
- Display: flex
- Align-items: flex-start
- Gap: `var(--space-2)` (8px) — same as active list items (D-82)
- Padding: `var(--space-2)` (8px) vertical, `var(--space-4)` (16px) horizontal — **same as active list rows**
- Border-bottom: 1px solid `var(--color-border)` — consistent separator
- Background: transparent

**Child elements:**

#### Habit Info Block (`.catalog-habit-info`)
- Flex: 1 (grows to fill available space)
- Min-width: 0 (allows text truncation)

**Habit Name (`.catalog-habit-name`)** — reuses existing class
- Display: block
- Font-weight: 400
- Font-size: 1rem (15px via CSS)
- Word-break: break-word
- Color: `var(--color-fg)` (#f5f5f5)
- Margin-bottom: `var(--space-1)` (4px) before badges

**Badges Container (`.catalog-habit-badges`)** — reuses existing class
- Display: flex
- Flex-wrap: wrap
- Gap: `var(--space-1)` (4px) — tight badge spacing
- Margin-top: `var(--space-1)` (4px) — separation from name

**Wave Badge (`.catalog-habit-wave`)** — reuses existing class
- Display: inline-block
- Padding: 2px 8px
- Border-radius: 12px
- Font-size: 0.75rem (11px)
- Font-weight: 400
- Background: `var(--color-surface-raised)` (#27272a)
- Color: `var(--color-fg-muted)` (rgba(245, 245, 245, 0.55))

**Start Date Badge (`.catalog-upcoming-date`)** — **new class for Phase 8**
- Display: inline-block
- Padding: 2px 8px
- Border-radius: 12px
- Font-size: 0.75rem (11px)
- Font-weight: 400
- Background: `var(--color-surface-raised)` (#27272a)
- Color: `var(--color-fg-muted)` (rgba(245, 245, 245, 0.55))
- **Content:** ISO date format (YYYY-MM-DD) per D-02. Example: `2026-08-15`
- Font-family: `var(--font-mono)` (optional; uses system monospace for consistent alignment)

#### Actions Block (`.catalog-habit-actions`) — reuses existing class
- Display: flex
- Flex-direction: column
- Gap: `var(--space-1)` (4px) — tight button stacking
- Flex-shrink: 0 — does not shrink; preserves button size

### Promote Button

**Element:** `<button class="catalog-btn catalog-btn--promote" data-action="promote" data-habit-id="{id}" aria-label="Promote {name} to active">`

**Base Styling (`.catalog-btn` — existing):**
- Display: inline-flex
- Align-items: center
- Justify-content: center
- Min-width: 44px
- Min-height: 44px (NFR-06, D-79)
- Padding: `var(--space-2) var(--space-2)` (8px 8px)
- Border: 1px solid `var(--color-border)`
- Border-radius: 6px
- Background: default (will inherit from body or default button background)
- Color: default (will inherit from text color)
- Font-size: 0.875rem (13px)
- Font-weight: 400
- Cursor: pointer
- White-space: nowrap
- Touch-action: manipulation

**Promote-specific styling (`.catalog-btn--promote` — new):**
- Follow the pattern of existing button variants (e.g., `.catalog-btn--archive`, `.catalog-btn--restore`)
- Background: **base button style** (not accent-colored) — matches Archive/Restore pattern
- Font-size: 0.8rem (12px) — compact, like Archive button (line 138 in catalog.css)
- Color: inherit from `.catalog-btn` default

**Hover/Focus states (inherited from `.catalog-btn`):**
- Background: `var(--color-surface-raised)` (#27272a)
- Outline: 2px solid `var(--color-focus)` (#3b82f6)
- Outline-offset: 2px

**Button text:** "Promote" (simple verb)

**Data attributes:**
- `data-action="promote"` — identifies the action handler in catalog.js
- `data-habit-id="{habitId}"` — UUID of the habit being promoted

**Aria label:** `"Promote {habit.name} to active"` — descriptive, includes context

**Interaction (D-05, D-06, D-07, D-08, D-09):**
- Direct action on click — no confirmation dialog
- Emits BroadcastChannel `{ type: 'habit:put', habitId }` on success
- Catalog re-renders immediately; promoted habit disappears from Upcoming, appears in active list
- Today view re-renders if the promoted habit is applicable for today's cadence

## Copywriting Contract

**Source:** Phase 8 CONTEXT.md decisions (D-05 through D-09, D-12), locked design decisions on UX flow.

| Element | Copy | Notes |
|---------|------|-------|
| **Section heading** | "Upcoming" | D-12; short, matches intent throughout ROADMAP.md and REQUIREMENTS.md |
| **Promote button label** | "Promote" | Simple verb; action is direct, no confirmation (D-05) |
| **Promote button aria-label** | "Promote {habit.name} to active" | Descriptive, context-rich for screen readers |
| **Edit button label** | "Edit" | Reuses existing label; allows pre-promote edit of startDate/cadence/stages (D-03) |
| **Empty state (Upcoming)** | (no copy) | Section is hidden entirely when empty per D-10; no placeholder or empty-state message |
| **Success feedback** | (implicit broadcast + re-render) | No toast or confirmation message; habit moves immediately to active list (D-06, D-09) |

**Assumptions:**
- User sees the habit move from Upcoming to active list on the same screen, confirming success
- No error states expected in Phase 8 scope (promote is a guaranteed state write)
- Destructive actions not in scope (D-04: No Archive button on Upcoming items)

## UI Considerations

**State coverage resolved for Phase 8:**

| Category | Element(s) | Status | Resolution |
|----------|------------|--------|-----------|
| **empty** | Upcoming section | ✅ covered | Section is hidden entirely when `upcomingHabits.length === 0` (D-10); no empty-state placeholder, no message |
| **zero-one-many** | Upcoming list | ✅ covered | Single item renders as a single row with action buttons; many items render as scrollable list, each with full visibility (no truncation of badges or buttons per minimum 44×44px constraint) |
| **long-text** | Habit name in Upcoming item | ✅ covered | `word-break: break-word` applied to `.catalog-habit-name` (existing CSS); wraps to next line if name exceeds container width |
| **overflow** | Many Upcoming habits (20+ items) | ✅ covered | List is within a scrollable catalog page; no horizontal overflow (text wraps, buttons stack vertically) |
| **interaction** | Promote button feedback | 🧪 backstop | Direct state change on click (no confirmation); habit disappears from Upcoming, appears in active list within same render cycle. Visual feedback is the re-render, not a toast (D-05, D-09). Verification: behavioral test in plan phase. |
| **sorted** | Upcoming list order | ✅ covered | Sorted ascending by `startDate` (D-11); soonest habit appears first, most actionable |
