  **logNumeric handler:**
  - Event payload: `{habitId, date, count}` (count = new total count for this (habitId, date); caller passes the new value)
  - Writes log row: `{habitId, date, count, definitionVersion: null}`
  - Does NOT write `completed` field (binary semantics); completion inferred as `count >= habit.target`
  - Captures prior log for inverse: `{type:'restoreLogRow', payload:{habitId, date, prior}}`
  - broadcastKeys: `{habitId, date}`

  **logSlot handler:**
  - Event payload: `{habitId, date, slots: [{name: string, checked: boolean}, ...]}` (full slots array; caller passes new state)
  - Writes log row: `{habitId, date, slots, definitionVersion: null}`
  - Captures prior log for inverse: `{type:'restoreLogRow', payload:{habitId, date, prior}}`
  - broadcastKeys: `{habitId, date}`

  Both handlers also recompute `lastCompletedDate` on the habit row using `_recomputeLastCompletedDate` from markUncompleted.js, but the "is completed" check for lastCompletedDate computation needs a helper that works for all log shapes. For now: numeric log's lastCompletedDate only counts if `count >= habit.target`; slot log's only counts if all slots are checked. Import the habit row and pass this context. If the new log IS completed (target met), treat it like markCompleted for the D-52 invariant.
  </behavior>
