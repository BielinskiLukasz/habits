## Context

### Analytics view data model (D-116)

The Analytics view reads from `score_snapshots` IDB store — NEVER calls `scoring.js` directly (SCORING-08).

**Data sources:**
1. `repo.getAllHabits()` → habit list (for names, wave, stage, status)
2. `repo.getSetting('scoringModel')` → active model (`'S1'|'S2'|'S3'`, default `'S1'`)
3. `repo.getSetting('masteryThreshold')` → global threshold (default 90)
4. For each habit: `repo.runTx(['score_snapshots'], 'readonly', tx => tx.objectStore('score_snapshots').get([habit.id, todayYMD]))` → today's snapshot row

The snapshot row shape: `{habitId, date, s1Score, s1Status, s2Score, s3Score, scoreVersion}`

**Analytics view layout** (D-116, UI-SPEC §Analytics View Layout):
- Header section: scoring dashboard summary — counts of Healthy/Watch/At-risk/Failing across all active habits (always S1 status regardless of active model)
- Active model radio buttons: inline with the dashboard header
- Below the header: `<table class="analytics-table">` with columns:
  - Habit name (left-aligned)
  - Stage (`habit.stage` → "Etap 1" / "Etap 2" / "Etap 3", or empty if stage is 0/null)
  - Rolling % + S1 badge (always shown; badge colored per s1Status)
  - Mastery badge ("Mastered" label, shown only when `habit.status === 'mastered'`)
  - Active model score (shown only when model is S2 or S3; the column header changes to "S2 score" or "S3 score")
- Rows grouped by wave: a wave header row (`<tr class="analytics-wave-header"><td colspan="5">Wave N — <wave name></td></tr>`) precedes each wave's habits
- Archived habits: hidden by default; a "Show archived" toggle checkbox in the header reveals them at 0.4 opacity via `.analytics-row--archived` class

**Reactive model switching** (D-117):
- The view subscribes to `store.subscribe(render)` — when the model changes (via Settings), `store.notify()` fans out and the view re-reads the active model and re-renders the score column header + values
- The radio buttons in the Analytics view header are a SECONDARY display of the current model (mirroring Settings). Changing the radio here calls `apply({type:'setSetting', payload:{key:'scoringModel', value}})` — same path as the Settings card

### Pure builders pattern (D-26)

`js/views/desktop/analytics.js` exports:
- `buildAnalyticsHeader({ statusCounts, scoringModel })` — returns description tree for the top dashboard
- `buildAnalyticsTable({ habitsByWave, snapshots, scoringModel, showArchived })` — returns description tree for the habit table
- `mountAnalytics(parent, { repo, store })` — live DOM mount; subscribes to store; reads IDB; calls builders; uses `mount()` from `js/util/mount.js`

The mount function follows the `today.js` idempotency pattern: checks if the panel is already mounted and skips re-building the skeleton; updates only reactive parts on `store.notify()`.

### Wave data for grouping

`repo.getAllHabits()` returns habits with `habit.wave` (number 0–9). Wave names come from the wave catalog loaded via `domain/wave.js` / `bootWaves()`. Use `store.cache.waves` (if available) or fall back to `"Wave N"` label format.

### T2: GREEN — Implement analytics view

**Type:** feat
**Files:**
- [new] `js/views/desktop/analytics.js`
- [new] `tests/unit/views/desktop/` (directory — created by test in T1)

**Implementation spec:**

File header: `/** @file Analytics view for desktop shell (DESKTOP-03, D-116, SCORING-02, SCORING-03). Reads from score_snapshots — never calls scoring.js. */`

**`buildAnalyticsHeader({ statusCounts, scoringModel })`:**
- `statusCounts`: `{ Healthy: number, Watch: number, 'At-risk': number, Failing: number }`
- Returns:
  ```
  { tag: 'div', attrs: { class: 'analytics-header' }, children: [
    { tag: 'div', attrs: { class: 'analytics-status-summary' }, children: [
      // 4 spans: "Healthy: N", "Watch: N", "At-risk: N", "Failing: N"
    ]},
    { tag: 'div', attrs: { class: 'analytics-model-selector' }, children: [
      { tag: 'span', text: 'Scoring Model: ' },
      // 3 labels with radios (same pattern as buildScheduleCard)
    ]},
  ]}
  ```
- Each status summary span: `{ tag: 'span', attrs: { class: 'analytics-status-count analytics-status-count--<lower>' }, text: '<Status>: <N>' }`
  where `<lower>` is the lowercase status slug (e.g., `healthy`, `watch`, `at-risk`, `failing`)

**`buildAnalyticsTable({ habitsByWave, snapshots, scoringModel, showArchived })`:**
- `habitsByWave`: `Array<{ waveNumber: number, waveName: string, habits: habit[] }>` — pre-sorted by wave
- `snapshots`: `Map<habitId, snapshotRow>` — today's snapshot per habit (or `null` if not yet computed)
- Returns `{ tag: 'table', attrs: { class: 'analytics-table' }, children: [thead, ...rows] }`
- `thead` columns: `['Habit', 'Stage', 'Rolling %', 'Mastery', ...activeModelColumn]`
  - When `scoringModel === 'S1'`: 4 columns (no model score column)
  - When `scoringModel === 'S2'`: 5 columns, last header = `'S2 Score'`
  - When `scoringModel === 'S3'`: 5 columns, last header = `'S3 Score'`
- For each wave group: one `<tr class="analytics-wave-header">` + one `<tr>` per (non-archived OR showArchived) habit
- Habit row cells:
  1. Name: `{ tag: 'td', text: habit.name }`
  2. Stage: `{ tag: 'td', text: habit.stage >= 1 ? \`Etap ${habit.stage}\` : '' }`
  3. Rolling % + S1 badge: `{ tag: 'td', children: [ {tag:'span', text: \`${s1Score ?? '—'}%\`}, {tag:'span', attrs:{class:\`score-badge score-badge--${statusSlug(s1Status)}\`}, text: s1Status ?? '—'} ] }`
  4. Mastery: `{ tag: 'td', text: habit.status === 'mastered' ? 'Mastered' : '' }`
  5. Active model score (when S2 or S3): `{ tag: 'td', attrs: {class: 'analytics-model-score'}, text: scoringModel === 'S2' ? (snap?.s2Score != null ? snap.s2Score.toFixed(2) : '—') : (snap?.s3Score != null ? snap.s3Score.toFixed(2) : '—') }`
- Archived rows: add `class: 'analytics-row--archived'` when `habit.status === 'archived'`
- Skip archived rows entirely when `!showArchived`

Helper: `function statusSlug(s1Status) { return ({Healthy:'healthy', Watch:'watch', 'At-risk':'atrisk', Failing:'failing'})[s1Status] ?? 'na'; }`

**`mountAnalytics(parent, { repo, store })`:**
- Idempotency guard: `if (parent.dataset.mounted === 'analytics') return;` — set `parent.dataset.mounted = 'analytics'` after first mount
- Async data fetch:
  1. `const habits = await repo.getAllHabits()`
  2. `const scoringModel = (await repo.getSetting('scoringModel')) ?? 'S1'`
  3. For each habit: fetch today's snapshot from `score_snapshots` store (use `repo.runTx`)
  4. Build `snapshots` Map and `habitsByWave` array
- Build description trees via builders, render via `mount()` from `js/util/mount.js`
- Subscribe to `store.subscribe(async () => { /* re-read scoringModel + snapshots, re-render */ })`; call `store.unsubscribe` on panel hide (if pattern exists) or just re-render on every notify
- "Show archived" toggle: a `<label><input type="checkbox"> Show archived</label>` above the table; on change, rebuild table description with updated `showArchived` flag
