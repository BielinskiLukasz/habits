## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | vanilla DOM + CSS (no framework) |
| Icon library | none (glyphs + Unicode symbols only) |

| Token | Value | Usage |
|-------|-------|-------|
| --space-1 | 4px | Icon gaps, inline padding |
| --space-2 | 8px | Compact element spacing |

| --space-5 | 24px | Card/panel padding, section breaks |

## Color

Locked from Phase 1 (D-16, tokens.css) with Phase 6 additions for scoring status:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) — Background | #0f0f10 (--color-bg) | Page background, default surface |
| Dominant (60%) — Foreground | #f5f5f5 (--color-fg) | Body text, default contrast |
| Secondary (30%) — Surface | #18181a (--color-surface) | Cards, panels, raised surfaces |
| Secondary (30%) — Surface Raised | #27272a (--color-surface-raised) | Badge backgrounds, secondary containers |
| Accent (10%) — Accent | #f5a623 (--color-accent) | Interactive elements (buttons, links), call-to-action |
| Accent soft | rgba(245, 166, 35, 0.18) (--color-accent-soft) | Hover states, focus rings, backgrounds for accent-contained buttons |
| Muted text | rgba(245, 245, 245, 0.55) (--color-fg-muted) | Secondary labels, disabled state, mastered habit muted opacity |
| Faint text | rgba(245, 245, 245, 0.32) (--color-fg-faint) | Tertiary labels, minimal contrast |
| Border | rgba(255, 255, 255, 0.08) (--color-border) | Dividers, input borders, card borders |
| Danger (destructive only) | #c0392b (--color-danger, inline fallback) | Reset data button text/border (from settings.css) |
| **[NEW] Score — Healthy** | **#10b981** (--color-score-healthy) | S1 status "Healthy", wave-board green cells, positive completion |
| **[NEW] Score — Watch** | **#f59e0b** (--color-score-watch) | S1 status "Watch", wave-board yellow cells, moderate caution |
| **[NEW] Score — At-risk** | **#f97316** (--color-score-atrisk) | S1 status "At-risk", wave-board orange cells, elevated caution |
| **[NEW] Score — Failing** | **#ef4444** (--color-score-failing) | S1 status "Failing", wave-board red cells, critical status |
| **[NEW] Score — Not Applicable** | **#6b7280** (--color-score-na) | Wave-board grey cells, habit not applicable on that day/week |

**Color Allocation (60/30/10 principle):**
- **60% Dominant:** dark bg (#0f0f10) + light fg (#f5f5f5) — maximizes readability and reduces eye strain in the dark theme.
- **30% Secondary:** surface colors (#18181a, #27272a) — card/panel backgrounds, badge backgrounds, visual hierarchy.
- **10% Accent:** amber (#f5a623) + scoring status colors — interactive elements (buttons, CTA links) + scoring badges. Scoring status colors (healthy/watch/at-risk/failing) are reserved ONLY for S1 status display and wave-board cells; they do NOT appear on every button. The 10% accent role is split: amber for interactive CTAs, status colors for scored-outcome visualization.

**Accent reserved for:**
1. Primary CTA buttons (e.g., "Create habit", "Export CSV", "Recompute scores")
2. Interactive links (e.g., "Switch to desktop view" in Settings)
3. Footer/sidebar nav active state highlighting
4. Accent-contained button backgrounds (where amber is the fill)
5. **NOT** on non-interactive elements or habit names

**Scoring Status Colors reserved for:**
1. S1 status badges in Analytics view (per-habit row: "Healthy" / "Watch" / "At-risk" / "Failing" badge)
2. Wave-board cell background colors (habit × week grid, S1 status heat-map)
3. No other use; status colors never appear on buttons or primary UI elements

**Dark theme only** — Light theme deferred post-v1. All tokens assume `@media (prefers-color-scheme: dark)` or system default dark.

## Layout & Interaction

### Desktop Shell Structure

**Desktop HTML (`desktop.html`)** mirrors the mobile shell structure but with a sidebar + multi-panel layout:

```
<body>
  <header><!-- Desktop header with title, optional theme toggle --></header>
  <nav><!-- Sidebar nav: Analytics / Wave-board / Planning links --></nav>
  <main>
    <section data-route="analytics" class="route-panel"><!-- Analytics view --></section>
    <section data-route="waveboard" class="route-panel" hidden><!-- Wave-board view --></section>
    <section data-route="planning" class="route-panel" hidden><!-- Planning view --></section>
  </main>
  <script type="module" src="./js/desktop.js"></script>
</body>
```

**Sidebar nav layout:**
- Fixed left sidebar (or sticky on scroll), width ~200px (using `--space-6` = 32px base units, so ~6–8 units wide).
- Three nav links: `#analytics`, `#waveboard`, `#planning` (matching desktop routes).
- Current-page link styled with `aria-current="page"` + accent underline or highlight (reusing Settings footer nav pattern from mobile).
- Dark theme: sidebar uses `--color-surface` background, `--color-fg` text.

**Main content area:**
- Full-width panels (right of sidebar).
- Each route panel fills the viewport or scrolls if content exceeds available height.
- `[hidden]` attribute controls visibility (same as mobile `data-route` pattern).

### Responsive Behavior

**P6 Desktop is desktop-first only:**
- Not responsive to mobile viewport widths.
- Wave-board horizontally scrollable if > 12 weeks of data; sticky left column (habit names) when scrolling right.
- No mobile-desktop breakpoint handling (that's a P7+ concern if needed).

### Analytics View Layout

**Header + Scoring Dashboard:**
- Active model selector: three radio buttons (S1 / S2 / S3) at top, label "Scoring Model" or inline with dashboard.
- Scoring summary counts: small cards or a single row showing "Healthy: N", "Watch: N", "At-risk: N", "Failing: N" (S1 only, regardless of active model).

**Habit list (grouped by wave):**
- Flat list, NOT collapsed/expandable wave sections.
- Wave name as a sticky or visually-distinct group header (e.g., background color `--color-surface-raised`, bold text).
- Per-habit row columns:
  1. Habit name (left-aligned, may wrap)
  2. Current stage (e.g., "Etap 2") — 13px, muted text
  3. Rolling % + S1 status badge (e.g., "85% Healthy") — status badge colored (green/yellow/orange/red per S1 status), regardless of active model
  4. Mastery badge (if applicable) — "Mastered" label only visible if habit is mastered
  5. Active model score (numeric, S2 or S3 if selected) — only shown in this column when model is S2 or S3

**Sorting / Filtering:**
- Default: sorted by wave (Fala 0 → 9), then by habit creation date within each wave.
- Optional "Show archived" toggle: hidden by default, reveals archived habits with greyed-out row style (opacity 0.4).

### Wave-board Heat-map Layout

**Structure:**
- X-axis: ISO week columns (e.g., "W26", "W27", …), 12-week default window, scrollable.
- Y-axis: habits grouped by wave (wave name as a sticky/distinct row).
- Cell value: S1 status for that habit over that week.

**Cell Styling:**
- Background color encodes status: green (Healthy) / yellow (Watch) / orange (At-risk) / red (Failing) / grey (N/A).
- Cell text or `title` attribute shows the status name + week summary (e.g., "Healthy (6/7 days applicable)").
- Accessibility: never rely on color alone — always include text or `title` (NFR-07).

**Archived habits:**
- Hidden by default.
- "Show archived" checkbox/button in header; when toggled, archived habits appear with greyed-out row style (opacity 0.4) and grey cell backgrounds.

### Planning View Layout

**Structure:**
- X-axis: ISO week columns (future weeks, 12-week default window).
- Y-axis: waves (consistent with Analytics and Wave-board grouping).
- Cells: habit names or counts of habits scheduled to start in that week.

**Interaction:**
- Read-only in P6 (no drag-and-drop, no inline editing).
- Clicking a habit row navigates to `./index.html#catalog` (or with a habitId query param, if Catalog router supports it).
- Already-active habits (startDate in past) are not shown; the Analytics view covers them.

## Interactive States

**Route navigation (hash router):**
- URL hash `#analytics` → Analytics view visible.
- URL hash `#waveboard` → Wave-board view visible.
- URL hash `#planning` → Planning view visible.
- Unknown hash → defaults to `#analytics`.
- Same pattern as mobile: browser back/forward works; no full-page reload.

**Model switching (SCORING-03):**
- Radio buttons or `<select>` in Settings model-selector card.
- On change: calls `apply.js` `setSetting({key: 'scoringModel', value: 'S1|S2|S3'})`.
- `store.notify()` fans out → desktop view subscribers re-read snapshots and re-render columns.
- **No page reload.**
- Analytics view updates score column headers and values instantly.

**Recompute Scores button:**
- Button in Settings Data card, below Export/Import section.
- On click: triggers `rebuildAllSnapshots()` (all habits, all dates, all 3 models).
- Loading state: button disabled, text "Recomputing…", optional spinner icon.
- On complete: toast "Snapshots recomputed. All scores updated." and button re-enabled.
- Desktop view subscribers refresh automatically (same store.notify pattern as model switch).

**Hover / Focus states:**
- Interactive elements (buttons, links, nav items) use `--color-accent-soft` on hover (amber soft background).
- Focus ring: 2px outline in `--color-accent` (amber), offset -2px (visible on dark bg).
- Wave-board cells: optional tooltip on hover showing full status + day count.

## Accessibility (NFR-07)

- **Color contrast:** All text meets WCAG AA minimum 4.5:1 (dark theme + light text).
- **Color not alone:** Status badges always include text label (e.g., "Healthy", "Watch"). Wave-board cells include `title` attribute with status + day count.
- **Touch targets:** All interactive elements ≥ 44×44px (nav links, buttons, wave-board cells if clickable).
- **Keyboard nav:** Tab order follows visual layout (sidebar nav → main content). `aria-current="page"` on active nav link.
- **Screen reader:** Habit names, stage, status, mastery badge all have semantic markup (no visually-hidden duplicates needed — the structure is semantic).
