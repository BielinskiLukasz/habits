## Context

### Planning view data model (D-121)

The Planning view shows habits whose `startDate` is in the FUTURE (not yet started). It is a forward-looking calendar — already-active habits belong in Analytics.

**Data sources:**
1. `repo.getAllHabits()` — all habits (filter to `status !== 'archived'` AND `startDate > todayYMD`)
2. No snapshot data needed — this is purely a scheduling calendar, not a scoring view

**Filter logic:**
- `todayYMD` = today's date (YYYY-MM-DD)
- Include habit if: `habit.startDate > todayYMD` AND `habit.status !== 'archived'`
- "Active" habits (startDate ≤ today) are excluded — they're already in Analytics

**Grid structure** (UI-SPEC §Planning View Layout):
- X-axis: 12 future ISO weeks starting from NEXT week (not the current week)
- Y-axis: grouped by wave number (same grouping as Analytics + Wave-board)
- Cells: contain habit names scheduled to start in that week
- Empty state: if no habits have `startDate` in the next 12 weeks, show the empty state message

**Cell content:**
- For each (wave × week) cell: list of habit names whose `startDate` falls in that ISO week
- Each habit name is an `<a href="./index.html#catalog">` link (D-121 — read-only, clicking navigates to Catalog for editing)
  - The href links to `./index.html#catalog` — since the Catalog view does not currently support direct-to-habit navigation via URL param, just link to `./index.html#catalog` (the user can find the habit there)
  - The link opens in the same tab (no `target="_blank"` — keeps navigation simple)

**Wave grouping:**
- Even if a wave has no scheduled habits in the 12-week window, it is NOT shown (unlike Analytics which shows all waves)
- Only waves that have at least one habit in the window are rendered

### Empty state

If no habits match the filter (no future startDates in next 12 weeks):
- Heading: "No upcoming habit starts"
- Body: "Habits you plan to start in the future will appear here. Schedule them in the Catalog view."
- A link to `./index.html#catalog` in the body text

### Pure builders pattern (D-26)

`js/views/desktop/planning.js` exports:
- `buildPlanningHeader({ weeks })` — returns column headers
- `buildPlanningRows({ waveGroups, weeks })` — returns body rows
- `buildPlanningEmpty()` — returns empty state description tree
- `mountPlanning(parent, { repo, store })` — live DOM mount

### T2: GREEN — Implement planning view

**Type:** feat
**Files:**
- [new] `js/views/desktop/planning.js`

**Implementation spec:**

File header: `/** @file Planning view for desktop shell (DESKTOP-05, DESKTOP-06, D-121). Forward-looking 12-week grid of future habits. Read-only; clicking habits links to index.html#catalog. */`

**`buildPlanningHeader({ weeks })`:**
- `weeks`: array of `{ key: string, label: string }` — e.g., `[{key:'2026-W27', label:'W27'}, ...]`
- Returns `{ tag: 'tr', children: [ {tag:'th', text:'Wave / Habit'}, ...weeks.map(w => {tag:'th', text:w.label}) ] }`

**`buildPlanningRows({ waveGroups, weeks })`:**
- `waveGroups`: `Array<{ waveNumber: number, waveName: string, habits: habit[] }>` — only waves with at least one scheduled habit
- `weeks`: same as above
- Returns array of `<tr>` objects:
  - For each wave: one `<tr class="analytics-wave-header"><td colspan={weeks.length+1}>{waveName}</td></tr>`
  - For each habit in wave: one row with habit name + a cell per week
    - Habit name cell (first): `{ tag: 'td', text: habit.name }`
    - Week cell: if `habit.startDate` falls in that week → `{ tag: 'td', children: [{tag:'a', attrs:{href:'./index.html#catalog'}, text: habit.name}] }` else `{ tag: 'td', text: '' }`
  - Note: each habit occupies its own row (one row per habit), not one row per wave with multiple habits per cell

**`buildPlanningEmpty()`:**
- Returns:
  ```javascript
  { tag: 'div', attrs: { class: 'planning-empty' }, children: [
    { tag: 'h2', text: 'No upcoming habit starts' },
    { tag: 'p', children: [
      { tag: 'span', text: 'Habits you plan to start in the future will appear here. Schedule them in the ' },
      { tag: 'a', attrs: { href: './index.html#catalog' }, text: 'Catalog view' },
      { tag: 'span', text: '.' },
    ]},
  ]}
  ```

**`mountPlanning(parent, { repo, store })`:**
- Idempotency guard: `parent.dataset.mounted === 'planning'`
- Data fetch:
  1. `const allHabits = await repo.getAllHabits()`
  2. `const todayYMD = /* use date.js toYMD or format today */`
  3. Filter: `const futureHabits = allHabits.filter(h => h.startDate > todayYMD && h.status !== 'archived')`
- Compute 12 future weeks:
  ```javascript
  // Start from NEXT week (not current week) to show only future starts
  // Use the same isoWeekKey helper from waveboard.js (inline here or share via a util)
  const weeks = computeNextNWeeks(12, todayYMD); // [{key, label}, ...]
  ```
  Inline `computeNextNWeeks` in this file (do not import from waveboard.js to avoid cross-view coupling):
  ```javascript
  function computeNextNWeeks(n, fromYMD) {
    const weeks = [];
    let cursor = daysFrom(fromYMD, 7); // start from next week
    for (let i = 0; i < n; i++) {
      const key = isoWeekKey(cursor);
      const label = 'W' + key.split('-W')[1];
      if (weeks.length === 0 || weeks[weeks.length - 1].key !== key) {
        weeks.push({ key, label });
      }
      cursor = daysFrom(cursor, 7);
    }
    return weeks;
  }
  ```
- If `futureHabits.length === 0`: render `buildPlanningEmpty()` and return
- Otherwise:
  - Build `waveGroups` (group futureHabits by wave, only waves with at least one habit)
  - Render: `<table class="planning-grid"><thead>[buildPlanningHeader]</thead><tbody>[...buildPlanningRows]</tbody></table>`
- Subscribe to `store.subscribe()` for reactivity (new habits added in Catalog would change this view)

**ISO week helpers** (inline, same pattern as waveboard.js — duplicate intentionally to keep views independent):
- `getISOWeek(dateYMD)` → `{ year, week }`
- `isoWeekKey(dateYMD)` → `'YYYY-Www'`

Import `daysFrom` from `../../util/date.js`.
