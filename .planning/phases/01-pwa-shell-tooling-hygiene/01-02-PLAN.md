<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser main thread → SW thread | The SW thread is a separate runtime that mediates all `fetch` events for same-origin requests after activation |
| SW thread → network | The SW's `fetch(request)` call is the only outbound network channel (besides the manifest install pipeline); all responses are subject to same-origin filtering before entering the cache |
| Stored cache → main thread | Any cached response served back to the main thread carries the SW's authority; stale-or-tampered cache entries become trust violations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-CacheScope | Information Disclosure / Tampering | `sw.js` fetch handler | mitigate | Early-return when `url.origin !== self.location.origin`. Cross-origin requests are never intercepted, never cached, and never produce opaque responses. Source-asserted by the V14 grep gate. |
| T-01-StaleCache | Tampering | `sw.js` activate handler | mitigate | Versioned cache name (`nawyki-${APP_VERSION}`) + `caches.keys()` cleanup of every prior cache. Bumping APP_VERSION in `js/util/version.js` (Plan 01-01) is the only operation needed to invalidate the prior version. |
| T-01-OfflineFail | Denial of Service | `sw.js` fetch handler (SWR fallback) | mitigate | `staleWhileRevalidate` catches network errors and returns the cached copy. Cache-first branch for shell assets always serves from cache when present, regardless of network. NFR-04 + PWA-06 satisfied. |
| T-01-NoNet | Information Disclosure | `sw.js` source | mitigate | Zero `https://` URLs in source. Verified by `grep -E 'https?://' sw.js` returning empty. No telemetry, no third-party CDN, no preconnect. |
| T-01-V14 | Tampering | `sw.js` import path | mitigate | `importScripts('./js/util/version.js')` is relative and same-origin; module SW form (which fails silently on Firefox per Pitfall 4) is explicitly rejected per D-12 / research §Q2. |
| T-01-FileSafe | Denial of Service | `sw.js` registration on file:// | mitigate | The protection lives in Plan 03's `sw-register.js` (protocol guard + silent catch). This plan's `sw.js` is never reached on `file://` because registration silently no-ops. |
</threat_model>
