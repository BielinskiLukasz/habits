  <behavior>
    Signature: `mountRoutes({routes, onChange, target})`
    - `routes` is `Record<string, () => void>` keyed by hash including the `#` prefix (e.g. `{'#today': mountTodayFn, '#settings': mountSettingsFn, '#history': showHistoryPlaceholder}`)
    - `onChange(hash)` is called on every route change with the resolved hash (`#today`, `#settings`, or `#history`)
    - `target` is the window-like object (defaults to `globalThis.window`); injectable for Node tests

    Resolution rules:
    - On boot: read `target.location.hash`; if empty OR not in `Object.keys(routes)` → resolve to `#today`
    - On `hashchange` event: same resolution
    - When resolved hash differs from previous: call `routes[hash]()` and then `onChange(hash)`
    - When resolved hash is the same as the previous: no-op (do not re-invoke the route function)
    - On the very first call (no previous), always invoke `routes[hash]()` + `onChange(hash)`

    Initial behaviors:
    - `mountRoutes({routes: {'#today': mountFn, '#settings': fn2, '#history': fn3}, onChange: ocFn, target: fakeWindow})` where `fakeWindow.location.hash === ''` → invokes `mountFn` once, calls `onChange('#today')` once
    - With `fakeWindow.location.hash === '#settings'` → invokes the settings fn, calls `onChange('#settings')`
    - With `fakeWindow.location.hash === '#unknown'` → falls back to `#today`
    - Dispatching a hashchange event with `target.location.hash === '#settings'` after initial mount on `#today` → invokes the settings fn, calls `onChange('#settings')`
    - Re-mounting (calling `mountRoutes` again) is idempotent — the second call does not register a duplicate `hashchange` listener (use the same Pattern-S4 mounted-once guard).
  </behavior>
