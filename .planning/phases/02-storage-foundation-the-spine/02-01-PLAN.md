<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer machine → CI runner | Test code crosses; CI executes `node --test` on `actions/setup-node@v4` |
| dev server → filesystem | `scripts/serve.js` resolves URL paths to filesystem paths — path-traversal candidate |
| browser context → `crypto.randomUUID()` | UUID generation feeds merge-by-id seed loader (collision = data loss) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering / Info Disclosure | scripts/serve.js path resolution | mitigate | `filePath.startsWith(ROOT + sep)` guard verbatim from sleep-tracker; reject with 403 (per RESEARCH §Security Domain, Pitfall via sleep-tracker analog) |
| T-02-06 | Cryptography weakness | js/util/id.js fallback chain | mitigate | Primary path is `crypto.randomUUID()` (CSPRNG); first fallback is `crypto.getRandomValues` v4 (CSPRNG); final Math.random fallback is documented as rare-path only (per Pitfall 13). Tests assert RFC4122 v4 format. |
| T-02-SC | Tampering (supply chain) | actions/setup-node@v4 in ci.yml | mitigate | Pin major version `@v4` explicitly (no `@main` / floating tags) — only third-party action in the workflow. **No npm packages installed in CI** (D-47 strict no-npm). No Package Legitimacy Audit required because zero packages are installed. |
| T-02-CI | Tampering | CI trigger configuration | mitigate | Workflow MUST declare BOTH `on.push.branches: [main]` AND `on.pull_request.branches: [main]` per Pitfall 10 — a single-trigger workflow silently ungates PR merges. |
</threat_model>
