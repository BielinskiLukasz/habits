## Tasks

### Task 1 — Create apply.markSkipped.test.js integration test

**File**: `tests/integration/apply.markSkipped.test.js` (new file)

Model the test after `apply.markCompleted.test.js`. The test must cache-bust both `apply.js` and `store.js` with the same URL query tag to ensure the store instance is shared (Pitfall 9).

Cover these cases:

**a) Happy path — writes `status: 'skipped'` row**
- Configure `apply` with fake repo + fake broadcast + `_resetXxxForTest`
- Call `apply({ type: 'markSkipped', payload: { habitId: 'h1', date: '2026-08-01' } })`
- Retrieve the log row via `repo.getLog('h1', '2026-08-01')`
- Assert: `log.status === 'skipped'`
- Assert: `log.definitionVersion === null`
- Assert: no `completed` field on the row

**b) Does NOT update `lastCompletedDate` (D-52 not triggered)**
- Seed a habit row with `lastCompletedDate: null`
- Call `apply({ type: 'markSkipped', ... })`
- Retrieve the habit row
- Assert: `habit.lastCompletedDate` is still `null` (D-52 not triggered)

**c) Inverse shape — `restoreLogRow` with prior state**
- When no prior log exists: call markSkipped, retrieve event from IDB
- Assert: `event.inverse.type === 'restoreLogRow'`
- Assert: `event.inverse.payload.prior === undefined` (no prior row when first write)

**d) Broadcast keys — `{ habitId, date }`**
- Spy on broadcast
- Call `apply({ type: 'markSkipped', ... })`
- Assert: broadcast called with `{ type: 'mutation', event: 'markSkipped', keys: { habitId: 'h1', date: '2026-08-01' }, at: <any string> }`

**f) Defensive — missing habit row does not block the log write**
- Call `apply({ type: 'markSkipped', payload: { habitId: 'nonexistent-habit', date: '2026-08-01' } })`
- The handler only writes to `logs` (no habit lookup), so it should succeed
- Assert: `repo.getLog('nonexistent-habit', '2026-08-01')` returns a row with `status: 'skipped'`
- Assert: no habit row was created in `habits` store (handler does not touch habits)

**e) Undo round-trip — markSkipped → undo() restores prior state**
- Seed a prior `status: 'completed'` log row
- Call `apply({ type: 'markSkipped', ... })` — overwrites with `status: 'skipped'`
- Call undo (via `apply({ type: 'restoreLogRow', payload: { habitId, date, prior: <prior row> } })`)
- Assert: log is restored to `{ status: 'completed', ... }`

**Pattern**: Follow the cache-bust + configure pattern from `apply.markCompleted.test.js`. Use `tests/helpers/fake-idb.js` and `tests/helpers/fake-broadcast-channel.js`.

**Verify**: `node --test tests/integration/apply.markSkipped.test.js` — all tests pass.

### Task 2 — Add skipped → 'x' test to export.csv.test.js

**File**: `tests/unit/export.csv.test.js`

Add a new `describe` block after the existing "applicable, completed" block:

```js
describe('csvCellValue — binary habit, applicable, skipped', () => {
  test('returns "x" when binary habit has status:skipped log', () => {
    const habit = binaryHabit();
    const date = '2026-06-06';
    const logs = [{ habitId: 'h1', date: '2026-06-06', status: 'skipped' }];
    const ctx = makeCtx(logs);
    assert.equal(csvCellValue(habit, date, logs, ctx), 'x');
  });
});
```

**Note**: A `status: 'skipped'` log on an applicable day returns `'x'` — the user consciously skipped, so the cell is treated as non-applicable for that day from a data perspective.
