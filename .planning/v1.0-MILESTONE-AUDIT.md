## Integration Findings

### BLOCKER-01 — Export/Import DI seam never wired at boot ❌

**Root cause:** `configureExport({repo})`, `configureImport({repo, broadcast})`, and `configureBackupNag({repo})` are exported from their modules but never called in `js/main.js` or `js/desktop.js`. The module-level `_repo` variable stays `null` in production.

**Runtime failure path:**
- User clicks "Export JSON" in Settings → `settings.js:469` calls `exportJSON()` → `export.js:101-102` checks `if (!_repo) throw new Error('export: configureExport({repo}) not called')` → caught, shown as error toast → download never occurs.
- Same for `exportCSV()` (export.js:262) and `mergeImportedStores()` (import.js:123).

**Evidence:** `grep -rn "configureExport\|configureImport\|configureBackupNag" js/` returns hits only inside the module declarations and JSDoc — zero calls in any boot file.

**Broken requirements:** EXPORT-01, EXPORT-02, EXPORT-03, EXPORT-04, EXPORT-05, EXPORT-06, EXPORT-07, EXPORT-08, IMPORT-01, IMPORT-02, IMPORT-03, IMPORT-04, SETTINGS-03

**Fix (small):** Add three `configure*` calls to the `main.js` boot sequence (and `desktop.js` if Settings is accessible from desktop):
```js
import { configureExport } from './io/export.js';
import { configureImport } from './io/import.js';
import { configureBackupNag } from './io/backup-nag.js';

// After other DI seams, before bootSeed:
configureExport({ repo });
configureImport({ repo, broadcast });
configureBackupNag({ repo, localStorage: globalThis.localStorage });
```

### BLOCKER-02 — `import:done` cross-tab signal has no receiver ❌

**Root cause:** `sync.js` exports `onMessage(fn)` to register BroadcastChannel message listeners. This is never imported or called in `main.js` or `desktop.js`. The internal `listeners` Set in `sync.js` stays empty in production.

**Runtime failure:** After JSON import, `import:done` is broadcast → peer tab's `bc.addEventListener('message')` fires → iterates empty `listeners` → no action. Peer tabs never re-hydrate.

**Broken requirements:** IMPORT-04

---

### BLOCKER-03 — Regular mutation cross-tab sync also broken ❌

**Root cause:** Same as BLOCKER-02. Every `apply()` broadcasts `{ type: 'mutation', ... }` via `broadcast()` but no peer tab registers a listener via `onMessage()` to call `hydrate()` / `store.notify()` in response.

**Impact:** Two-tab usage shows stale data in Tab B after Tab A mutates. Single-tab usage unaffected.

**Broken requirements:** DATA-07

**Fix for BLOCKER-02 + BLOCKER-03 (small):**
```js
import { bootSync, broadcast, onMessage } from './platform/sync.js';

// After bootSync() and await hydrate():
onMessage(async (msg) => {
  if (msg.type === 'import:done') {
    await hydrate();
    // broadcast import:done to local subscribers via store.notify if needed
  } else if (msg.type === 'mutation' && msg.keys) {
    await hydrate(msg.keys);
  }
});
```

### WARNING-01 — `backup-nag.js` `_repo` never configured (degraded, non-crashing) ⚠

**Root cause:** `configureBackupNag({repo})` never called (same root as BLOCKER-01). `daysSinceLastBackup()` short-circuits at `if (!_repo) return null` — nag always renders as "no backup recorded" regardless of actual export history. The "Last backup: N days ago" line in Settings Data card is always absent.

**Broken requirements:** SETTINGS-04 (last-backup timestamp), EXPORT-08 (weekly nag)

**Fix:** Covered by the BLOCKER-01 fix above (`configureBackupNag({ repo, localStorage: globalThis.localStorage })`).

---

### WARNING-02 — Desktop analytics wave names render as "Wave N" (degraded display) ⚠

**Root cause:** `desktop.js` passes `{ subscribe }` (not the full store module) to `mountAnalytics`, `mountWaveboard`, and `mountPlanning`. `analytics.js` line ~362 checks `store.cache.waves` to resolve wave names, with a `"Wave N"` defensive fallback. Since `store.cache` is a module-internal variable not accessible via the `{ subscribe }` partial, the fallback always fires.

**Broken requirements:** DESKTOP-03 (partial — analytics renders correctly except wave names are generic)

**Fix (small):** In `desktop.js`, import the full store namespace:
```js
import * as store from './state/store.js';
// Then pass store (not { subscribe }) to all mount calls:
mountAnalytics(analyticsPanel, { repo, store });
```
